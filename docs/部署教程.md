# CampusHub 部署与维护

## 推荐方案：Render 免费静态页面 + Java 容器 + Neon PostgreSQL

先按下方步骤部署 Java 21 Docker 容器和 Neon PostgreSQL，再按文末「独立免费前端入口」部署 Static Site 并配置同源 API Rewrite。浏览器只访问静态站域名，Cookie 与 CSRF 仍保持同源；Docker 一体部署作为本机和其他主机的可选方案。

免费方案适合课程演示、个人项目与小规模试用。Render 免费服务在空闲后休眠，首次打开可能等待冷启动；Render 自带的免费数据库有 30 天到期限制。Neon 免费计划有存储、计算和流量额度，也会在空闲时暂停计算。具体额度以 [Render 官方说明](https://render.com/docs/free) 和 [Neon 官方套餐说明](https://neon.com/docs/introduction/plans) 为准。免费规则复核日期：2026-11-09。

### 1. 上传源码仓库

在 GitHub / GitLab 创建自己的仓库，将本目录源码推送上去。保留 `Dockerfile`、`backend`、`frontend`、`render.yaml` 和前端 lockfile。

`.gitignore` 已排除 `.tools/`、`.runtime/`、`.env`、依赖目录、构建输出及发布包；不要提交数据库文件或真实密码。

### 2. 创建 Neon 数据库

1. 登录 [Neon 控制台](https://console.neon.tech/)，选择免费计划创建项目，地区尽量靠近 Render 服务地区。
2. 创建一个专用数据库（例如 `campushub`）和拥有该数据库 schema 权限的角色。
3. 在连接面板找到 Host、Database、User 和 Password。首次部署可使用直接连接地址，应用连接池上限为 5。
4. 将连接参数转换成 JDBC 格式，**用户名密码单独填环境变量**：

```text
DB_URL=jdbc:postgresql://你的数据库主机:5432/campushub?sslmode=require
DB_USERNAME=你的数据库用户名
DB_PASSWORD=你的数据库密码
```

不要将 `postgresql://用户名:密码@主机/数据库` 原样写入 DB_URL，Java 使用 `jdbc:postgresql://`；不要把数据库密码提交到源码。

### 3. 创建 Render Web Service

1. 登录 [Render 控制台](https://dashboard.render.com/)，选择 **New → Web Service** 并连接源码仓库。
2. Runtime 选择 **Docker**，Dockerfile 为根目录 `./Dockerfile`，构建上下文为根目录。
3. 选择 **Free** 实例。若免费计划或注册流程发生变化，以平台当时显示的条款为准。
4. 健康检查路径设为 `/api/health`。
5. 配置以下环境变量：

| 变量 | 设置值 |
| --- | --- |
| DB_URL | 上一步 JDBC 地址，带 sslmode=require |
| DB_USERNAME | Neon 用户名 |
| DB_PASSWORD | Neon 密码 |
| ADMIN_USERNAME | admin 或符合规则的管理员用户名 |
| ADMIN_PASSWORD | 自定义、至少 12 位强密码 |
| SEED_DEMO | false |
| COOKIE_SECURE | true |
| TZ | Asia/Shanghai |

`PORT` 使用 Render 提供的值即可，Spring Boot 会读取它。Dockerfile 已使用 Java 21 JRE，并为小内存实例限制 JVM 堆、元空间和缓存；实际资源是否够用仍需部署后观察。

也可以选择 Blueprint 导入根目录 `render.yaml`，再填写标记为手动提供的数据库与管理员变量。此文件只创建 Web Service，不额外创建会过期的免费 Render PostgreSQL。

### 4. 部署与验收

部署成功后打开平台分配的 `https://你的服务.onrender.com`。前端静态资源由 Spring Boot 提供，API 路径保持 `/api`。

首次启动 Flyway 创建数据库结构，应用只创建管理员，不创建样本社团。登录管理员后台，依次添加社团、器材、活动；再注册一个学生账号，验证申请、审核、报名、签到、借还、报修和导出。

如果需要临时展示样本数据，可在首次启动前显式设置 `SEED_DEMO=true`。这会创建文档所列的演示学生账号，建议仅用于演示环境；关闭开关不会自动删除已写入数据库的样本账号或业务数据。

首次管理员密码只在账号不存在时使用。修改环境变量不会重置已经创建的账号密码，请在成员中心修改密码。

2026-11-07 已完成实际部署：公网地址为 [CampusHub](https://campushub-2ar9.onrender.com/#/clubs)，运行于 ZeroVector 工作区的 Render 免费 Docker 服务，数据库为新加坡区域 Neon PostgreSQL 17。此次通过服务创建接口配置环境变量，再在控制台设置 `/api/health` 健康检查；`render.yaml` 保留为自行部署模板，当前服务不由 Blueprint 管理。实际测试范围见 [云端验收记录](云端验收.md)。[Render 官方首次部署文档](https://render.com/docs/your-first-deploy) 说明了容器部署和域名分配流程。

## 本地 Docker Compose

安装 Docker Desktop 并启用 Linux 容器，在根目录执行：

```powershell
Copy-Item .env.example .env
# 使用编辑器替换 .env 中的数据库密码和管理员密码
docker compose up --build -d
docker compose ps
docker compose logs -f app
```

访问 http://localhost:8080。默认不开放数据库公网端口，仅应用容器能通过 `db:5432` 访问。PostgreSQL 在命名卷 `postgres-data` 中持久化，Flyway 自动迁移。

```sh
docker compose down
# 以上命令只停止并移除容器，保留命名卷中的数据
```

HTTPS 反向代理部署时，将 `COOKIE_SECURE=true`，代理转发到容器 8080；应用已经启用代理头解析。纯本地 HTTP 需要保持 false，否则浏览器不会发送 Secure Cookie。

## 独立 Linux / 云主机

准备 Java 21、Maven 3.9+、Node.js 22.12+ 或 24 LTS、PostgreSQL。先构建前端，再构建后端：

```sh
cd frontend && npm ci && npm run build
cd ../backend && mvn -DskipTests package
cd ..
export DB_URL='jdbc:postgresql://127.0.0.1:5432/campushub'
export DB_USERNAME='campushub'
export DB_PASSWORD='替换数据库密码'
export ADMIN_PASSWORD='替换至少12位管理员密码'
export SEED_DEMO=false
export COOKIE_SECURE=true
java -Xms64m -Xmx320m -jar backend/target/campushub-1.0.0.jar
```

以上跳过数据库测试的打包命令只用于部署构建，正式提交前仍应在独立测试库执行 `mvn verify`。服务进程可由 systemd 或现有容器平台管理，前方配置 HTTPS 反向代理。

## 数据备份

本机开发库使用 PowerShell 调用 PostgreSQL 工具，以文件参数输出，避免 PowerShell 重定向损坏二进制：

```powershell
. .\scripts\env.ps1
$env:PGPASSWORD=$env:DB_PASSWORD
& .\.tools\pgsql\bin\pg_dump.exe -h 127.0.0.1 -p 54329 -U campushub -d campushub -Fc -f .\campushub-backup.dump
Remove-Item Env:PGPASSWORD
```

Docker 容器内备份并复制出来：

```sh
docker compose exec -T db pg_dump -U campushub -d campushub -Fc -f /tmp/campushub.dump
docker compose cp db:/tmp/campushub.dump ./campushub-backup.dump
```

恢复时先创建新的空数据库，使用 `pg_restore --no-owner --no-privileges -d 新数据库 备份文件`。Neon 也可以通过标准 PostgreSQL 工具备份；备份不要放进公开仓库。

## 常见问题

| 情况 | 排查方式 |
| --- | --- |
| Java 版本不正确 | Windows 先执行 `. .\scripts\env.ps1`；IDEA 项目 SDK 和 Maven Runner 都选择 Java 21 |
| 首次启动管理员密码报错 | 生产环境设置至少 12 位 ADMIN_PASSWORD；本地演示通过脚本设置 SEED_DEMO=true |
| 数据库连接失败 | 检查 JDBC 前缀、主机、端口、用户名、密码、数据库存在性和云端 TLS 参数 |
| 登录提示安全令牌失效 | 刷新页面获取新 CSRF；确认同域代理和 COOKIE_SECURE 与 HTTP/HTTPS 一致 |
| Render 首次打开慢 | 免费实例休眠后的冷启动属于平台限制 |
| Vite 启动失败 | 确认 Node 版本及 5173 端口是否已占用 |
| Windows 打包时 JAR 被占用 | 使用项目启动脚本，它从 .runtime 运行副本；手动运行 target JAR 时先停止该进程再打包 |
| 页面可打开但不能报名 | 检查报名截止、名额、重复报名、活动是否取消和社团是否归档 |
| 签到按钮不能点 | 仅在开始前 30 分钟至结束期间开放，且必须已报名、尚未签到 |

## 2026-11-09 独立免费前端与当前线上后端

公网通过 [首页](https://zhengtu-cycling.onrender.com/#/) 或 [管理员后台](https://zhengtu-cycling.onrender.com/#/admin) 访问。当前 Java 21 Web Service 为 Oregon 的 `zhengtu-api-oregon`，数据库使用原新加坡 Neon PostgreSQL。账号和历史数据来自该数据库。原新加坡 Java 服务地址为历史部署入口。

1. 在 ZeroVector 工作区创建免费的 Docker Web Service，关联同一仓库 main。填写上文的数据库与安全环境变量，设置健康检查 `/api/health`。
2. 创建免费的 Static Site，构建命令为 `npm --prefix frontend ci --no-audit --no-fund && npm --prefix frontend run build`，发布目录为 `frontend/dist`。设置 `NODE_VERSION=24`。
3. 在静态站 Redirects/Rewrites 配置 `/api/*` 到 `https://zhengtu-api-oregon.onrender.com/api/*` 的 Rewrite。自行部署时换成自己的后端域名。Vue 使用 hash 路由，重写规则只覆盖 API。
4. 为静态站设置 `VITE_SERVICE_WAKE_URL=https://zhengtu-api-oregon.onrender.com/`。这是编译进浏览器的公开 HTTPS 地址。数据库密码、连接串和管理员密码由后端环境变量管理。
5. 前端与后端均采用手动部署。分别发布所需版本，等状态为 Live 后访问首页，再验证健康 JSON、登录、后台概览和一项带 CSRF 的写入。仅修改文档时可以保留当前线上版本。

免费 Java 实例闲置后仍会休眠，静态页面继续可访问。 [公网故障与验收记录](公网稳定性修复.md)
