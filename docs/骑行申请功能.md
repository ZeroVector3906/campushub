# 活动建议、骑行室使用与入社资料

用户登录后在「骑行活动」点击「活动建议」，填写建议名称、活动安排和联系方式，提交集体骑行活动申请；也可通过侧栏「活动建议」进入。建议通过后仍需管理员在「活动管理」正式发布活动，避免把建议误认为可直接报名的安排。

「骑行服务 → 骑行室使用」可选择和光文体中心俱乐部或北三骑行室，使用方式为训练、拿车、休息、其他；其他须填写具体用途。日期与小时/分钟分别选择，时间弹层可滚动选择时分。输入以北京时间保存，后端校验开始时间晚于当前、结束时间晚于开始。此功能是使用申请，不承诺独占场地，也不自动拒绝相同时段的多名使用者。

本人可查看自己的建议、使用申请和审核意见。管理员在「管理工作台 → 活动建议 / 骑行室」查看全部申请，包括申请人姓名、账号、学号、学院、联系方式、申请内容、场所、使用方式、起止时间、提交与处理时间；支持搜索、状态筛选及通过/驳回并填写意见。普通用户不能读取他人的申请或访问管理员接口。联系方式不提供公共接口。

「俱乐部展示 → 申请加入」增加联系方式、所在年级和所在学院，均为必填。信息随申请保存，管理员在「成员审核」查看；旧申请字段留空，不虚构历史资料。

## 数据库与 API

Flyway V5 在 memberships 增加 contact、grade、college，建立 riding_requests，保留旧业务表和记录。应用回退旧版本可保留这些新增表列，不需删除数据；回退前端时需注意旧入社表单缺少新必填字段，应刷新使用新页面。

- GET /api/riding-requests：本人的记录。
- POST /api/riding-requests：提交 SUGGESTION 或 ROOM 申请。
- GET /api/admin/riding-requests：管理员查看全部记录。
- PUT /api/admin/riding-requests/{id}/review：管理员处理申请。
- POST /api/clubs/{id}/applications：入社申请增加 contact、grade、college。

新接口沿用 BCrypt 登录会话、角色权限与 CSRF 校验。不重置现有账号密码。测试只使用明确标记的测试申请，不冒充真实使用预约。
